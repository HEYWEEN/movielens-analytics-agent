# 项目路线与验收顺序

本路线以课程《项目总体要求与汇报安排》为验收依据。各轮只使用实际运行结果；后一轮读取前一轮产物时先校验清单、版本和时间边界。

## 迭代一：Hadoop 数据治理（9 月 30 日汇报）

1. [x] 登记课程输入版本、默认清洗规则与五维评分方案。
2. [x] 一次自然语言请求触发 Hadoop 清洗前评分、清洗、清洗后评分；展示状态和失败原因。
3. [x] 生成清洗文件、异常隔离、未核验冲突、评分报告、T1/T2 与可核验清单。
4. [x] 前端展示五维对比、处置情况、样例与依据；支持围绕真实报告追问。
5. [x] 在当前机器完成全量 Hadoop Streaming 运行，并与本地验证交叉核对文件 SHA-256。
6. [x] 保存实验配置、结果、方法局限和演示命令；见 `iteration1-experiment.md`。

现场建议按“输入请求 → 看三阶段进度 → 看五维与处置 → 追问评分依据 → 展示作业 ID 与清单”演示。先运行 `./start.sh --hadoop`，确认页面显示 Hadoop 引擎。提交源码时保留输入数据和运行产物在 Git 忽略目录，交付实验记录与可复现命令。

## 迭代二：分类、聚类、降维（10 月 21 日或 11 月 11 日汇报）

1. **输入契约**：校验迭代一清单和未核验标记；冻结 `8891cc6d797569c0`、`ml1m-rules-v4`、`T1/T2`。若重新清洗得到新版本，应显式开启新实验，不能混合旧模型。
2. **时间切分与特征**：训练仅使用 T1 及以前记录；验证使用 (T1, T2]；测试使用 T2 之后。画像特征只由对应时间范围内可见的信息构造，防止泄漏。
3. **分类**：从课程 PPT 的分类算法中选两种，预测评分是否不低于 4；各自注册独立 Agent 工具，保存模型、参数、评价指标和版本。
4. **聚类**：用训练期的用户偏好画像，选两种 PPT 算法；保存群体标签、画像解释、指标与版本。
5. **降维**：选两种 PPT 算法，在相同输入上比较信息保留、聚类影响与资源开销；保存模型和坐标。
6. **验收**：两种算法的真实输出可由 Agent 单独调用，前端能展示结果及依据；模型清单指向同一个已验证的迭代一输入。

算法最终名单需按课程 PPT 确定，避免选到不在指定范围内的方法。

## 迭代三：知识图谱与图任务（12 月 2 日或 12 月 23 日汇报）

1. 校验并读取第一轮清洗数据、第二轮模型及用户群体，统一图谱输入版本和训练截止时间。
2. 构建用户、电影、类型等实体及评分、类型关系；为实体和边记录来源、T1 与版本，完成图谱校验并发布清单。
3. 在同一个图谱版本或其有记录的投影上，分别实现推荐、图挖掘、链接分析；每类从 PPT 选两种算法，各自注册工具并记录参数、指标与结果。
4. 图谱缺失、校验失败或版本不一致时拒绝运行上层任务；前端展示实际结果、依据和失败原因。
5. 进行时间切分和跨版本检查，确认测试期信息未进入训练图或训练特征。

## 跨轮约束

- 输入版本、规则版本、模型版本、图谱版本和任务 ID 贯穿全部报告与清单。
- 没有真实产物时明确返回未完成或失败，不能在前端展示占位成绩。
- 大模型 API 不是课程的硬要求；若后续接入，只负责理解与解释，不替代 Hadoop、算法工具及可核验结果。
