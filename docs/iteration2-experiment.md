# 迭代二实验记录：分类、聚类、降维与分析 Agent

## 目标、输入与证据状态

本轮在迭代一的清洗产物上实现六个可独立调用的算法工具：逻辑回归、决策树、KMeans、Ward 层次聚类、PCA、NMF。分类预测一个用户对一部电影在未来一次评分中是否会打出不低于 4 分；聚类描述训练期用户画像；降维压缩同一画像并比较压缩前后的聚类结构。DeepSeek 只负责选择工具与解释已登记结果，模型训练和指标计算均由本地算法完成。

分类课件 `26Fall-008-分类1010+1014.pdf` 明确列有 Decision Tree 与 Logistic Regression。聚类和降维对应的课程 PPT 尚未拿到，KMeans、Ward 层次聚类、PCA、NMF 是已实现的候选算法，**不能据此宣称四种均已通过课程 PPT 算法范围核对**。

## 时间切分与特征

评分事件按 `timestamp` 划分：训练 `<= T1` 共 800,168 行，验证 `(T1,T2]` 共 100,021 行，测试 `> T2` 共 100,020 行。正类定义为评分 `>= 4`。训练行的用户、电影历史统计只读取**严格早于该行时间戳**的评分；同一秒的多行互不可见。验证、测试及在线预测都使用冻结在 `T1` 的历史统计，验证和测试标签不会回填特征。

分类特征包含用户静态属性、电影类型和发行年份，以及事件前的用户/电影评分次数、均值、高分率和有无历史标记。静态元数据按数据集给出的版本使用；数据集没有逐属性的生效时间，因此这里只能保证动态评分历史无未来泄漏。验证期有 611 个用户、16 部电影在训练期没有历史；测试期相应为 200 个用户、33 部电影，使用冷启动特征，不能把这一评估口径解释为“已有历史用户专属效果”。训练期已评分的同一用户电影组合不作为新的在线预测目标。

用户画像仅由训练期评分构成：18 个类型的观影占比、18 个平滑平均评分与整体高分率，共 37 维。至少有 20 条训练期评分的 5,301 位用户进入聚类；739 位已知用户因历史不足被明确标记。画像经 MinMax 缩放后供四个无监督算法使用，原始与缩放后的完整 37 维向量都保存于 `profiles.json`。

## 分类：两种算法与常数基线

逻辑回归比较 `C=0.3/1.0`，决策树比较深度 `8/12`、叶节点至少 50 行。候选按验证集 PR-AUC、再按 F1 选择；每个候选的分类阈值也只在验证集搜索。测试集在方案确定后评价一次。训练集正类率为 0.5787，因此“恒定输出训练集正类率、阈值 0.5”的简单基线会在测试期全部预测为高分。

| 测试期方法 | F1 | PR-AUC | Precision | Recall | 选择结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| 常数正类率基线 | 0.7050 | 0.5444 | 0.5444 | 1.0000 | 固定阈值 0.5 |
| 逻辑回归 | 0.7454 | 0.7610 | 0.6173 | 0.9405 | `C=1.0`，阈值 0.3 |
| 决策树 | 0.7450 | 0.7555 | 0.6193 | 0.9348 | 深度 8，阈值 0.3 |

两模型相对常数基线有改进，但阈值 0.3 使召回率高、精确率较低。单个用户电影组合返回的是模型概率及预测类别，不是该用户的真实未来评分。以 `UserID=635, MovieID=1` 为可复核例子，T1 前未出现该组合；逻辑回归高分概率为 0.9241，决策树为 0.9169，均判为高分。这是特定模型和版本的预测，不能说用户已经给出高分。

## 聚类：群体描述与分离程度

KMeans 和 Ward 层次聚类在相同 5,301 位用户、相同 37 维训练画像上划为 5 群。群体编号只在各自算法内有意义。轮廓系数取固定随机种子的最多 1,200 位用户样本；Davies–Bouldin 指数用全部合格用户。

| 方法 | 轮廓系数 | Davies–Bouldin | 拟合耗时 |
| --- | ---: | ---: | ---: |
| KMeans | 0.1128 | 2.0267 | 0.198 s |
| Ward 层次聚类 | 0.0713 | 2.3269 | 0.290 s |

两个轮廓系数均较低，说明当前画像没有形成清晰分离的群体。群体解释只报告训练期的相对观影类型占比和代表影片，不把它当作稳定人格或成因判断。例如 KMeans 群体 0 的 Drama 观影记录占比比所有合格用户高 7.75 个百分点。KMeans 与 Ward 不支持噪声标签，因此查询结果 `is_noise=false` 表示算法没有噪声类别，不等于证明用户数据无噪声。

## 降维：信息、聚类对照与资源

默认从 37 维压缩到 2 维。两算法共用**中心化重建 R²** `1 - SSE/SST` 比较重建保留情况；PCA 另报告解释方差和。未中心化的能量比不作为两算法的主比较值。NMF 在本次配置下迭代 382/2,000 次并收敛。

| 方法 | 中心化重建 R² | 原始空间 KMeans 轮廓 | 压缩标签放回原空间的轮廓 | 压缩后标签与原标签 ARI | 降维拟合耗时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| PCA | 0.4729 | 0.1128 | 0.0928 | 0.4920 | 0.001 s |
| NMF | 0.4166 | 0.1128 | 0.0221 | 0.1568 | 0.032 s |

在各自的二维空间中，KMeans 轮廓系数分别为 PCA 0.3142、NMF 0.3727；由于距离空间已经变化，这两个较大的数**不能单独证明聚类改善或信息保留更好**。压缩标签放回原 37 维空间的轮廓系数都低于原始聚类，NMF 的一致性下降更明显。报告同时保存两种聚类算法在原空间与压缩空间的对照、输入与坐标矩阵字节数、模型大小及拟合耗时。`coordinates.json` 保存实际目标维数的完整坐标；网页图只绘前两维。

参数化实验另生成 `b1a5e1e20006`（4 群、3 维）和 `b1a5e1e20007`（4 群、中心化重建 R² 阈值 0.5）：两次都通过清单验收。阈值任务依次尝试 2、3 维，PCA/NMF 都在 3 维达到阈值；耗时记录为所尝试维数的总拟合时间。任务参数变化产生新的模型与清单，查询时不能拿旧模型冒充新配置。

## Agent、前端与交付产物

网页提供会话、进度、三类分析对照、二维图、来源文件和追问。`POST /api/agent/chat` 只通过 DeepSeek 选择已登记工具；六个算法各有独立工具，也可请求同类双算法对照。用户可以指定 `UserID`/`MovieID`、1–20 个用户的集合、群体数、目标维数或信息保留阈值。用户集合只筛选已发布模型的查询结果和坐标，不会仅对这批用户重新拟合模型；改变群体数、维数或阈值要创建新任务。未知 ID、历史不足、模型未完成和与已发布配置不一致的请求均返回明确状态。无密钥时，报告和算法任务仍可通过页面入口及 API 访问，但对话返回 `missing_api_key`。

默认任务产物：`report.json`（切分、配置、指标、限制）、`models.joblib`（已训练模型与冻结状态）、`profiles.json`（完整画像）、`clusters.json`（群体）、`coordinates.json`（完整降维坐标）、`manifest.json`（摘要与版本）。这些文件在 `runs/iteration2/<analysis_task_id>/`，均被 Git 忽略。DeepSeek API Key 只保留在服务端进程环境，不进入前端、报告或仓库。

2026-10-19 使用真实 `deepseek-flash` 验证了问候、现有报告解读、连续工具调用和自然语言任务创建：“635号用户会喜欢1号电影吗”实际调用分类对照；“分成3个群体并压缩到2维”被解析为 `n_clusters=3, target_dimensions=2`，创建任务 `220d6e6c420e` 并完成清单验收。验证记录保存在本机忽略目录 `runs/agent-validation/20261019/live-check.json`。网页通过 `/api/agent/stream` 实时展示阶段和工具事件；输入空用户集合不再阻止普通对话。工具提供了真实指标，但模型的因果、显著性和可靠性推论仍需审阅；这些调用验证不能等同于对所有模型解释的正确性证明。
