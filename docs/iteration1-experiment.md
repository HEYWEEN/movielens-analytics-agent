评分前后始终使用 `pipeline.py` 中同一套公式。Accurate 是字段、取值、引用和未核验冲突的代理指标，不能证明真实世界准确性；Complete 检查必需字段；Unique 检查业务键冗余；Up-to-date 以 2003-02-28 日终为固定参照、计算此前 365 天的有效评分比例；Consistent 检查结构、冲突和引用。每个维度的实际分子/分母在 `report.json` 的 `score_evidence` 中。

## 异常处置与解释

| 处置 | 行数 | 含义 |
| --- | ---: | --- |
| 完全重复去重 | 34,742 | 删除多余的相同业务记录 |
| 冲突变体隔离 | 15,325 | 同一业务键的非选中变体，不将其称为已修复 |
| 无效或孤立记录隔离 | 101,453 | 字段、取值、结构或跨表引用不能通过检查 |
| 规范化后最终保留的修复行 | 0 | 本次没有可计入最终保留的修复行；规范化输入计数不能冒充修复量 |
| 保留但未核验的同频冲突 | 322 | 用户 217、电影 105；为下游提供稳定选中值，同时附带未核验标记 |

移除合计 151,520 行，等于三个表的前后行数差；322 条未核验行属于**保留行**，不加入移除数。Up-to-date 略升来自清洗后评分记录的组成变化，没有把旧时间戳改成新日期。清洗后 Accurate 仍低于 100，反映同频冲突保留项没有外部证据可以确认。另有人口属性自填、电影信息和评分真实性无法仅靠本数据集验证。

## 交叉验证与局限

全量 Hadoop 和全量本地验证分别运行后，三个清洗文件的 SHA-256 **逐一相同**，数据版本同为 `8891cc6d797569c0`；本地模式仅用于验证规则一致性。独立的清洗前与清洗后 Hadoop 评分作业也分别与清洗作业报告对上。12 个单元及集成测试通过，网页 API 的单次请求、进度、报告、清单和追问均已实际验证。

本轮单 reducer 聚合约百万条数据，尚未验证多节点扩展性能。规则路由只支持项目约定的中文请求与追问范围，不具备通用自然语言理解；文档没有要求必须接入大模型。下一轮使用数据时应校验 `manifest.json` 并读取 `unresolved_conflicts.jsonl`，沿用相同输入版本、规则版本及 T1/T2；训练数据只能位于 T1 之前。
